## 为什么不把 File-Sharing-Bot 说成已上线

从其仓库原始文件核对，启动至少要：

- `TG_BOT_TOKEN`（BotFather）
- `APP_ID` / `API_HASH`（[my.telegram.org](https://my.telegram.org)，要你的手机号登录，我这边没有）
- `DATABASE_URL`（MongoDB，本机没有现成库）
- `CHANNEL_ID`（再做一个私人仓库频道的数字 ID）
- `OWNER_ID`
- `FORCE_SUB_CHANNEL`

另外两项是实打实的风险，不是猜测：

1. 依赖的 [pyrogram/pyrogram](https://github.com/pyrogram/pyrogram) 在 GitHub 上 **`archived: true`**，最后 push 是 2024-12-23。
2. `config.py` 里写死了 `ADMINS.append(1250450587)`，等于官方示例默认塞进一个第三方管理员 ID。
3. 最新 commit `0fb4745`（2025-12-28）只改了 README 的 Star History，不是功能修复。

所以：这个项目「有名」是真的；「我已经替你跑通」是假的。本次不部署它。

本机一套官方 [Telegram Bot API](https://core.telegram.org/bots/api) 长轮询程序，目录：`频道推广手册/bot/`。

- 不需要 Telegram 会员
- 不需要 MongoDB

能不能用，只看 `验证结果.md` 里的接口返回，不看这页的愿望。
